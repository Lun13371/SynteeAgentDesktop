# Цели (`/goal`) и управление контекстом Syntee

## `/goal` — семантика Claude Code

Цель — это **условие завершения**, а не промпт. Пока цель активна, агент не
останавливается после одного ответа: он продолжает ходы, пока условие не станет
истинным.

```text
/goal npm test выходит с кодом 0 и линтер чист
```

Команда:
- `/goal <условие>` — поставить или **заменить** цель и сразу начать ход (условие
  и есть задание, отдельный промпт не нужен). До 4000 символов.
- `/goal` — статус: условие, сколько идёт, сколько ходов оценено, расход токенов,
  последний вердикт.
- `/goal clear` (алиасы `stop`, `off`, `reset`, `none`, `cancel`, а также
  `/goal-stop`) — снять цель досрочно.
- `/goal-resume` — продолжить активную цель с этого места; `/goal-pause` —
  приостановить цикл (следующее сообщение возобновит его).
- `/clear` также снимает активную цель.
- Одна цель на чат; новая заменяет старую.

## Ключевое: работу судит не тот, кто её делает

После каждого хода **отдельная быстрая модель** (роль `fast`, без инструментов)
читает транскрипт и выносит один из трёх вердиктов:

| Вердикт | Что происходит |
|---|---|
| **met** | условие выполнено — цель снимается как достигнутая, вердикт остаётся в карточке |
| **not_met** | ещё нет; причина уходит в следующий ход как указание |
| **impossible** | условие невыполнимо — цель снимается с причиной |

Оценщик видит только переписку, поэтому условие должно быть проверяемым по
выводу агента: «npm test выходит с кодом 0», «git status чист», «в CHANGELOG.md
есть запись для каждого PR». Слова модели «готово» доказательством не считаются.

Границы задаются клаузой в самом условии («…или остановись после 20 ходов»).
Отдельного жёсткого лимита времени нет; поле «максимум раундов» в редакторе
цели — необязательный предохранитель (0 = без лимита).

## Остановки и ошибки

- Несколько ходов подряд без инструментов — цикл приостанавливается с
  предупреждением, **цель остаётся set**; оценка возобновится с вашего
  следующего сообщения.
- Неисправимая ошибка (истёк доступ, кончились кредиты, переполнение контекста,
  модель недоступна) — цель снимается с указанием причины: «Запусти /goal заново».
- Транзиентная ошибка (сеть, 5xx, rate limit) — цель остаётся активной.
- Падение/перезапуск приложения — цель сохраняется и продолжится со следующим
  сообщением (проверить состояние нужно самому: в прогресс пишется пометка).
- Права доступа цель не меняет: если нужен approval, агент спросит.

Технические проверки не заменяют запуск в живом Electron-клиенте с реальным
провайдером.

## Контекст

Счётчик контекста — точка входа в управление источниками. История использует
существующие флаги скрытия и закрепления сообщений, общие с редактором чата.
Скрытие исключает сообщение из следующих запросов; оно не удаляет его из истории
или у провайдера.

Настройки источников относятся к следующим запросам и автоматическому
подмешиванию. Они не отменяют уже отправленный запрос и не являются запретом на
явный вызов инструмента чтения или поиска.

Базовые системные правила, разрешения и защита не отключаются. Состояние цели
передаётся независимо от сжатия переписки.

## Ручная проверка

1. Поставить цель: `/goal <проверяемое условие>`; агент должен начать работу без
   дополнительного промпта.
2. `/goal` без аргументов — статус (условие, время, ходы, токены, последний
   вердикт).
3. Проверить, что карточка цели показывает вердикты оценщика и растёт счётчик
   ходов.
4. Незавершаемое условие → вердикт `impossible`, цель снимается с причиной.
5. `/goal clear` и `/clear` — цель исчезает; `/goal-pause` + любое сообщение —
   цикл продолжается.
6. Проверить изоляцию чатов: цель одного чата не влияет на другой.
7. Перезапустить приложение во время цели: цель должна остаться активной.
