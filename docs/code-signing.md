# Подпись кода (SignPath Foundation)

Бесплатная подпись для открытых проектов. Нужна, чтобы Windows не показывал
«Неизвестный издатель» и не блокировал фоновую установку обновлений.

## Что даёт и чего не даёт

| | |
|---|---|
| Стоимость | 0 € |
| Publisher в диалоге | **SignPath Foundation** (не `Syntee`) |
| Что проверяют | сборку из исходников, лицензию, активность проекта |
| Ручное подтверждение | каждый релиз — вручную в панели SignPath |

Publisher — это SignPath Foundation, потому что сертификат выдан им. Для
личного OSS-проекта это норма. Если нужно своё имя в диалоге — только платный
сертификат (Certum Open Source, ~49 €/год).

## Требования (проверено по signpath.org/terms.html)

| Требование | Статус проекта |
|---|---|
| OSI-лицензия без коммерческого dual-licensing | ✅ MIT |
| Нет проприетарного кода | ✅ обфускация удалена |
| Проект активно поддерживается | ✅ |
| Уже выпущен в том виде, что подписываем | ✅ |
| Функциональность описана на странице загрузки | ⚠️ нужен README/лендинг (README есть) |
| MFA у всех участников (GitHub и SignPath) | ⚠️ включить |
| Роли Authors / Reviewers / Approvers | ⚠️ завести в панели |
| Нет функций для взлома/обхода защиты | ✅ |

## Как подать заявку

1. Включить 2FA на GitHub (`Settings → Password and authentication`).
2. Зарегистрироваться на https://signpath.io и создать организацию.
3. Подать заявку через https://signpath.org (кнопка Apply).
4. Указать репозиторий `https://github.com/Lun13371/SynteeAgentDesktop`,
   лицензию MIT, ссылку на Releases как страницу загрузки.
5. Дождаться ревью (обычно 1–2 недели).
6. После одобрения в панели SignPath:
   - создать проект и артефакт-конфигурацию для NSIS `.exe`;
   - выпустить API-токен (Settings → API tokens);
   - задать политику подписи с ручным подтверждением.

## Секреты в GitHub

Добавить в `Settings → Secrets and variables → Actions`:

| Секрет | Откуда |
|---|---|
| `SIGNPATH_API_TOKEN` | панель SignPath → API tokens |
| `SIGNPATH_ORGANIZATION_ID` | URL панели: `/organizations/<id>` |
| `SIGNPATH_PROJECT_SLUG` | настройки проекта |
| `SIGNPATH_SIGNING_POLICY_SLUG` | настройки политики подписи |
| `SIGNPATH_ARTIFACT_CONFIG_SLUG` | конфигурация артефакта (NSIS) |

Пока секретов нет — workflow пропускает шаг подписи, сборка идёт как раньше.
Как только они заведены, подпись включается сама.

## Как это работает в CI

```
собрать .exe → загрузить в SignPath → дождаться одобрения вручную →
скачать подписанный .exe → опубликовать в релизе
```

Ручное одобрение — это фича, а не помеха: битый билд просто не подписывается,
и пользователи его не получат. Это заменяет `bad_versions` из старого лаунчера.

## Проверка подписи

```powershell
Get-AuthenticodeSignature .\Syntee-Helper-Setup-1.1.5-x64.exe | Format-List
```

Ожидаемо: `Status = Valid`, `SignerCertificate.Subject` содержит
`SignPath Foundation`.

## До подписи

Обновления работают и без сертификата — но SmartScreen может показать
предупреждение при фоновой установке. Для текущего числа пользователей
(десяток человек, в основном разработчики) это допустимо.
