## Текущая структура

```
src/
├── core/       ← бизнес-логика (не зависит от Electron)
├── main/       ← главный процесс Electron
├── preload/    ← мост безопасности
├── renderer/   ← UI на React
└── shared/     ← типы и константы
```

Это **классический Electron-паттерн** по разделению процессов. Хорошая база.

## Что в ней хорошего ✅

| Аспект | Оценка |
|---|---|
| **Разделение процессов** (main/preload/renderer) | ✅ Стандарт, правильно |

| **IPC-хендлеры разнесены по файлам** | ✅ Хорошо |

## Что можно улучшить ⚠️

### 1. **God-файлы** (самая большая проблема)

Некоторые файлы слишком большие — это антипаттерн:

| Файл | Размер | Проблема |
|---|---|---|
| `core/tools/index.ts` | **79 КБ** | Один файл — все инструменты. Нужно разбить по доменам |
| `core/agent/Agent.ts` | **59 КБ** | Слишком много ответственности в одном классе |
| `main/ipc/chat.ipc.ts` | **55 КБ** | Один файл на весь chat-IPC |
| `core/ai/AIClient.ts` | **29 КБ** | Великоват |
| `main/ai-worker.ts` | **27 КБ** | Великоват |
| `core/db/database.ts` | **25 КБ** | Все таблицы/запросы в одном файле |

### 2. **Нет чёткого разделения слоёв внутри `core/`**

Сейчас `core/` — это "всё в одну кучу". Нет разделения на:
- **domain** (сущности: Chat, Message, Project, Memory)
- **application** (use-cases: RunAgent, SendMessage)
- **infrastructure** (db, ai-client, external APIs)

### 3. **`renderer/components` не структурирован по фичам**

Сейчас: `components/ui`, `components/layout`, `components/settings` — это группировка **по типу**, а не **по фиче**. Для крупного проекта лучше feature-based.

## Альтернативные структуры

### Вариант A: **Feature-Based** (рекомендуется для масштабирования)

```
src/
├── main/              ← Electron main (как сейчас)
├── preload/           ← как сейчас
├── renderer/
│   ├── features/      ← фичи вместо "по типам"
│   │   ├── chat/
│   │   │   ├── ChatPage.tsx
│   │   │   ├── ChatInput.tsx
│   │   │   ├── MessageBubble.tsx
│   │   │   ├── chat.store.ts
│   │   │   └── useChatRun.ts
│   │   ├── settings/
│   │   ├── memory/
│   │   └── overlay/
│   ├── shared/        ← общие UI-компоненты (Button, Modal)
│   └── App.tsx
├── core/
│   ├── domain/        ← сущности и правила
│   │   ├── chat/
│   │   ├── agent/
│   │   ├── memory/
│   │   └── project/
│   ├── infrastructure/← реализация (db, ai, fs)
│   │   ├── database/
│   │   ├── ai-client/
│   │   └── tools/     ← разбить на файлы!
│   └── application/   ← use-cases (оркестрация)
│       ├── RunAgent.ts
│       └── SendMessage.ts
└── shared/            ← типы, константы
```

### Вариант B: **Модульный монолит** (проще, для среднего проекта)

```
src/
├── main/
├── preload/
├── renderer/
├── core/
│   ├── chat/          ← всё про чат: tools, agent-logic, types
│   ├── memory/        ← всё про память
│   ├── ai/            ← LLM-клиент
│   └── db/            ← миграции, репозитории
└── shared/
```

### Вариант C: **Tauri-стиль** (Rust backend, если бы не Electron)

Неактуально для текущего стека, но упомяну для полноты — там backend на Rust, frontend отдельно.

## Оценка текущей структуры

```
 ████████████████░░░░  8/10
```

**Вердикт: структура хорошая, но не идеальная.** Для проекта на текущей стадии — полностью достаточна. Но есть **два главных риска**:

1. 🔴 **God-файлы** (`tools/index.ts` — 79КБ, `Agent.ts` — 59КБ) — при росте проекта это станет бомбой замедленного действия. Любое изменение затрагивает огромный файл, тяжело ревьюить, тяжело тестировать.

2. 🟡 **Нет feature-разделения в renderer** — пока фич немного, терпимо. Но если их будет 10+, начнётся путаница "где лежит компонент X".
