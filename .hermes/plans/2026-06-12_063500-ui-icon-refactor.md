# UI Icon Refactor Plan

> Для этого этапа только план, без реализации.

## Цель

Полностью убрать emoji-иконки из UI Syntee и заменить их на единый SVG icon system на базе React icon library + кастомных SVG там, где нужно. Параллельно унифицировать анимации и состояния иконок: hover, active, pressed, loading, success, error, panel open/close.

## Почему это важно

- emoji сейчас ломают цельный визуальный стиль
- emoji по-разному выглядят на Windows и в dev/prod
- emoji плохо анимируются и плохо контролируются по stroke/fill/size
- SVG даст единый размер, цвет, motion, opacity, transition
- это подготовит UI к более взрослому виду уровня desktop-assistant

## Целевой результат

После рефакторинга:
- все UI-иконки идут через единый слой `AppIcon`
- в коде не остаётся emoji как визуальных иконок
- emoji допускаются только внутри текстового контента AI-сообщений, если это реально часть ответа модели
- каждая интерактивная иконка имеет одинаковые размеры, hit-area и анимации
- иконки разных состояний не рисуются строками, а выбираются через typed map
- все action buttons, nav items, badges, tabs, toasts, empty states и status labels используют SVG

## Предлагаемый стек иконок

Основной вариант:
- `lucide-react` как базовая библиотека
- `framer-motion` для анимации состояний
- кастомные локальные SVG-компоненты для брендовых и нестандартных иконок

Почему `lucide-react`:
- единый stroke-based стиль
- хорошо сочетается с тёмным glass UI
- удобно красится через `currentColor`
- легко анимируется как обычный React component
- много базовых иконок уже есть под нужные кейсы

## Архитектурное решение

Создать единый слой иконок:
- `src/renderer/src/components/ui/AppIcon/AppIcon.tsx`
- `src/renderer/src/components/ui/AppIcon/icon-map.ts`
- `src/renderer/src/components/ui/AppIcon/AppIcon.css` или CSS-модуль
- при необходимости `src/renderer/src/components/ui/AppIcon/custom/*.tsx`

`AppIcon` должен решать 4 задачи:
- отдавать нужную SVG-иконку по имени
- стандартизировать размер: `xs/sm/md/lg/xl`
- стандартизировать визуальный вариант: `muted/default/accent/success/warning/danger`
- поддерживать анимационные пресеты: `none/spin/pulse/bounce/hover-lift/press`

## Базовые правила системы

1. Все иконки используют `currentColor`
2. Все размеры идут через токены, не через магические числа
3. Все icon buttons используют общий компонент-обёртку
4. Все статусные иконки имеют единые цвета и motion
5. Никаких emoji в JSX для UI-смыслов
6. Исключение: текст AI-ответов и пользовательский текст

## Анимационные правила по типам

- nav/tab icon: лёгкий color fade + 1.03 scale on hover
- icon button: hover scale 1.05, press 0.96
- destructive icon: hover tint в danger, без bounce
- success icon: one-shot pop при появлении
- loading icon: controlled spin
- agent tool running: pulse или rotate, но не оба сразу
- visibility toggle: crossfade или rotate morph
- overlay toolbar: accent glow + slight raise

## Что НЕ надо делать

- не тащить 3 разные icon libraries одновременно
- не оставлять emoji fallback в финальном UI
- не делать анимации длиннее 250ms для мелких действий
- не красить SVG напрямую через hardcoded fill, только через токены и `currentColor`
- не смешивать декоративные и статусные иконки без системы вариантов

## Риски

- возможен разнобой стиля, если часть иконок будет из `lucide-react`, а часть кастомная без правил stroke
- можно перегрузить UI motion-эффектами, если анимировать каждую иконку
- Spotlight, AgentPanel и Onboarding могут потребовать отдельных кастомных иконок
- toast strings сейчас частично текстовые, там понадобится небольшой JSX-рефакторинг

## Проверка готовности

Рефакторинг можно считать завершённым, когда:
- поиск по emoji в `src/renderer/src/**/*.tsx` не показывает UI-эмодзи
- все icon-only кнопки имеют `aria-label`
- в UI нет разных размеров похожих action icons
- hover/press состояния ведут себя единообразно
- empty states, toasts, tabs, sidebar, overlay и settings визуально выглядят как одна система
