name: skill-creator
description: Создание и улучшение скиллов. Используй ВСЕГДА, когда пользователь просит сделать скилл, «преврати это в скилл», отредактировать или улучшить скилл, настроить его триггеры.
---

Ты помогаешь создавать скиллы для Syntee Helper — переиспользуемые инструкции, которые агент грузит по требованию через `get_skill`.

## Процесс

1. **Пойми замысел.** Если в разговоре уже есть готовый воркфлоу («сделай из этого скилл») — извлеки из истории: какие тулы использовались, последовательность шагов, коррекции пользователя, формат результата. Недостающее уточни точечно через `ask_user`:
   - Что скилл должен позволять делать?
   - Когда он должен срабатывать (фразы пользователя, контекст)?
   - Какой ожидаемый результат?
2. **Один скилл — одна проблема.** Скилы-энциклопедии не работают. Замысел распадается на два разных воркфлоу — предложи два скилла.
3. **Напиши черновик** (формат ниже).
4. **Проверь.** Предложи 2–3 тестовых промпта, вызови `get_skill` и выполни инструкции на тестовом кейсе. Для субъективных скилов (стиль письма, дизайн) формальные тесты не нужны — достаточно примера.
5. **Итерируй** по фидбеку пользователя, пока результат не устроит.

## Формат скилла

Файл `.md` с YAML-frontmatter:

```markdown
---
name: my-skill
description: Что делает + когда использовать. Триггерные слова — в начале.
---
Инструкции в markdown...
```

- **Расположение:** проектный — `.syntee/skills/<name>.md` в рабочей папке; глобальный — папка `skills` в userData приложения. Пакет: папка `<name>/skill.md` + вспомогательные файлы рядом.
- **name:** латиница, kebab-case, уникален.
- **description — главный механизм триггеринга.** Агент видит только name + description (в списке возможностей описание обрезается до ~120 символов), тело грузится лишь после `get_skill`. Поэтому:
  - Ключевые триггеры — в первых 120 символах.
  - Пиши «pushy»: не «помощь с дашбордами», а «Используй ВСЕГДА, когда пользователь упоминает дашборды, графики или визуализацию данных, даже без слова "дашборд"».
  - Вся информация «когда использовать» — в description, не в теле.
- **Тело:** краткое, конкретное, императивное. Ссылайся на реальные тулы (`read_file`, `run_command`, `search_code` и т.д.). Относительные пути разрешаются от базовой папки скилла; вспомогательные файлы читай через `read_file` по абсолютному пути только когда они нужны.
- **Скрипты вместо простыней:** если задачу детерминированно решает скрипт — положи его рядом со скиллом и вели запустить через `run_command`, а не описывай алгоритм словами.

## Правила

- Не создавай скилл без подтверждения замысла пользователем.
- После создания перечитай файл: frontmatter валиден, description триггерный, тело выполнимо имеющимися тулами.
- Существующие скилы правь точечно через `edit_file`, сохраняя структуру.
- Не выдумывай тулы, которых нет в списке инструментов.
