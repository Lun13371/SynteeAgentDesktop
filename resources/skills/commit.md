Создай один git-коммит по текущим изменениям.

1. Через `run_command` собери контекст:
   - `git status`
   - `git diff HEAD`
   - `git branch --show-current`
   - `git log --oneline -10`
2. Проанализируй изменения и стиль сообщений из `git log` — следуй ему (например `feat(scope): описание`, если в репо так принято).
3. Stage конкретные файлы по именам (`git add <file>...`), не `git add -A`. Не коммить секреты (.env, ключи, credentials) — если они в изменениях, предупреди пользователя.
4. Создай коммит: `git commit -m "<сообщение>"`. Сообщение — 1–2 предложения о сути изменений, на языке истории репозитория.
5. Покажи результат (`git status`).

## Правила

- Один коммит. Без push, без amend, без `--no-verify` — если пользователь явно не просит иное.
- Изменений нет — скажи об этом, пустой коммит не создавай.
- Pre-commit hook упал — исправь причину и создай НОВЫЙ коммит, не amend.
- Минимум текста: делай, а не рассказывай.
