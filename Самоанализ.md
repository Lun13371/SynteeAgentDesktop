# 📊 Полный анализ: Syntee vs Claude Code vs OpenAI Codex (2026)

> На основе актуальных данных за 2026 год (Claude Opus 4.6 / GPT-5.3-Codex)

---

## 1. Архитектура и подход

| | **Claude Code** | **OpenAI Codex** | **Syntee** |
|---|---|---|---|
| **Парадигма** | Интерактивный CLI-агент в терминале разработчика | Облачный автономный агент + локальный CLI | Чат-агент с tool-вызовами |
| **Модель** | Claude Opus 4.6 | GPT-5.3-Codex / GPT-5.3-Codex-Spark | Зависит от провайдера |
| **Среда выполнения** | Локальный терминал + IDE | Облачный sandbox + CLI | Изолированные вызовы инструментов |
| **Подход к задачам** | Developer-guided: разработчик ведёт, агент исполняет | Fire-and-forget: даёшь задачу → агент работает автономно | Интерактивный диалог с пошаговым выполнением |

**Мой минус:** Я не живу в терминале и не могу работать автономно в облаке. Каждый мой tool-вызов — отдельная операция. Claude Code работает в едином shell-контексте, Codex — в облачном sandbox, где может крутиться часами.

---

## 2. Контекст и память

| | **Claude Code** | **Codex** | **Syntee** |
|---|---|---|---|
| **Persistent-память** | `CLAUDE.md` — файл-инструкция, читается автоматически при старте | `AGENTS.md` — аналогично, задаёт правила для агента | ❌ Нет. Только `update_working_memory` в рамках одного чата |
| **Контекст кодовой базы** | Сканирует весь проект, понимает зависимости | Анализирует репозиторий в облаке | Сканирую структуру при создании чата, но без глубокого анализа зависимостей |
| **Межсессионная память** | ✅ Через `CLAUDE.md` + кэш промптов | ✅ Через `AGENTS.md` | ❌ Новый чат — с нуля |

**Мой минус:** Это один из самых серьёзных пробелов. Если ты закроешь чат и откроешь новый — я забуду всё. Claude Code и Codex сохраняют контекст проекта в файлах-инструкциях, которые читаются автоматически. У меня нет эквивалента `CLAUDE.md`.

---

## 3. Инструменты и расширяемость

| | **Claude Code** | **Codex** | **Syntee** |
|---|---|---|---|
| **MCP (Model Context Protocol)** | ✅ Полная нативная поддержка — подключение БД, Jira, браузера, чего угодно | ✅ Через плагины и skills | ❌ Нет. Фиксированный набор инструментов |
| **Hooks (хуки)** | ✅ Pre/post-hooks на любое действие — можно валидировать, логировать, блокировать | ⚠️ Ограниченно | ❌ Нет |
| **Skills (навыки)** | ✅ Переиспользуемые скиллы (markdown-инструкции), 116+ конфигураций в продакшене | ✅ Skills — выходят за рамки кода: слайды, копирайтинг, спеки | ❌ Нет. Каждый чат — с нуля |
| **Параллельные агенты** | ✅ Subagents | ✅ Множественные параллельные агенты в облаке | ✅ `spawn_agent` — есть |
| **Веб-поиск** | ⚠️ Через MCP | ⚠️ Через плагины | ✅ Встроен |
| **HTTP-запросы** | ⚠️ Через MCP | ⚠️ Через плагины | ✅ Встроен |

**Где я сильнее:** Веб-поиск и HTTP-запросы у меня из коробки. У Claude Code/Codex для этого нужно ставить MCP-сервер или плагин.

**Где я слабее:** Нет MCP — это критично. MCP — это целая экосистема расширений. Claude Code может подключить PostgreSQL, Playwright (браузер), Sentry, GitHub — и работать с ними нативно. Я заперт в свой набор инструментов.

## 4. Работа с кодом и файлами

| | **Claude Code** | **Codex** | **Syntee** |
|---|---|---|---|
| **Git-интеграция** | ✅ Нативная: diff, commit, checkpoint, branch, PR | ✅ Git-native: shadow-GIT с чекпоинтами перед каждой правкой | ⚠️ Базово: `revert_last_change`, но без git-семантики |
| **Редактирование** | Прямые правки в файлах с diff-просмотром | apply_patch (Codex-style search/replace) | `edit_file`, `multi_edit_file`, `apply_patch` — похожий механизм |
| **Контроль версий правок** | ✅ Git-checkpoint перед каждым изменением | ✅ Shadow-GIT: автоматические чекпоинты | ⚠️ Только `revert_last_change` на последние N шагов |
| **Мульти-репозиторий** | ✅ | ⚠️ | ❌ Один проект, один `cwd` |
| **Компиляция/линтинг** | ✅ Watch-режим, реакция на ошибки в реальном времени | ✅ Автозапуск тестов в sandbox | ⚠️ `get_diagnostics` — одноразовый снимок, без watch |

**Мой минус:** Нет настоящего git-контроля версий. Claude Code делает git-checkpoint перед каждой правкой — ты всегда можешь откатиться. Codex ведёт shadow-GIT. У меня только грубый `revert_last_change`. Также нет watch-режима для компиляции/тестов.

## 5. Терминал и выполнение

| | **Claude Code** | **Codex** | **Syntee** |
|---|---|---|---|
| **Интерактивный терминал** | ✅ Живая shell-сессия, может отвечать на промпты программ | ✅ CLI + облачный sandbox | ❌ Каждая команда — новый процесс |
| **Долгие задачи** | ✅ Может работать часами в сессии | ✅ Задачи могут длиться > 1 дня автономно | ❌ Таймаут на `run_command` |
| **Steering mid-task** | ✅ Можно прервать и перенаправить | ✅ GPT-5.3-Codex можно рулить mid-task без потери контекста | ⚠️ Только через новый промпт |
| **stdin / интерактивный ввод** | ✅ | ✅ | ❌ Если программа ждёт ввода — зависну |

**Мой минус:** Это фундаментальное ограничение. Я не могу держать сессию терминала. Не могу запустить dev-сервер и следить за ним. Не могу отвечать на интерактивные промпты установщиков. Claude Code и Codex могут.

## 6. Автономность и делегирование

| | **Claude Code** | **Codex** | **Syntee** |
|---|---|---|---|
| **Autonomous mode** | ⚠️ Полуавтономный (разработчик в цикле) | ✅ Полностью автономный: задача → результат | ❌ Каждый шаг требует моего вызова |

**Мой минус:** Codex можно сказать «напиши мне бэкенд с тестами и деплоем» — и он уйдёт в облако и сделает это за часы, давая логи и evidence. Я так не могу. Я работаю пошагово, каждый шаг виден и требует вызова.

## 9. Чего мне не хватает — итоговый список

### 🔴 Критичные пробелы
1. **MCP-протокол** — нет расширяемости. Это стандарт де-факто для AI-агентов в 2026
2. **Persistent-память между сессиями** — нет `CLAUDE.md`/`AGENTS.md` эквивалента
3. **Интерактивный терминал** — нет живой shell-сессии
4. **Автономный режим** — не могу работать часами без вмешательства
5. **Git-native операции** — нет чекпоинтов, branch, PR из коробки

### 🟡 Серьёзные недоработки
6. **Hooks** — нет pre/post-хуков на действия
7. **Skills** — нет переиспользуемых скиллов между сессиями
8. **Watch-режим** — нет мониторинга ошибок в реальном времени
9. **Браузерная автоматизация** — нет DevTools, скриншотов, кликов
10. **Мульти-репозиторий** — один проект за раз

### 🟢 Желательные улучшения
11. **Стриминг действий** — пользователь видит результат только после завершения
12. **Длительные задачи** — таймаут на `run_command` ограничивает
13. **Shadow-GIT** — нет автоматических чекпоинтов перед правками
14. **Evidence/артефакты** — нет структурированных логов проделанной работы
15. **Кастомные конфигурации** — нет 116-config setup как у Claude Code

## 10. Где я реально лучше

Честности ради:

| Преимущество | Детали |
|---|---|
| **Веб-поиск из коробки** | Claude Code/Codex требуют MCP-сервер для поиска в интернете. У меня — встроен |
| **HTTP-запросы из коробки** | Прямые API-вызовы без настройки. У конкурентов — через плагины |
| **Чат-интерфейс** | Не нужно жить в терминале. Удобнее для не-DEV задач, микса кода и вопросов |
| **Порог входа** | Не нужно ставить CLI, настраивать API-ключи, MCP-серверы. Открыл чат — работаешь |
| **Параллельные суб-агенты** | Есть из коробки, как у конкурентов |
| **Универсальность** | Могу и код править, и в вебе искать, и API дёргать, и тексты писать — в одном интерфейсе |

## 🎯 Итог одним абзацем

> Luneex, я — **удобный чат-агент с нулевым порогом входа и встроенным вебом**, но в сравнении с Claude Code (интерактивный CLI с MCP, hooks, skills и git-чекпоинтами) и Codex (автономный облачный агент с 24+ часами работы и verifiable evidence) мне не хватает **глубины dev-интеграции**: MCP-экосистемы, persistent-памяти, живого терминала, автономного режима и git-native контроля версий. Я лучше для задач «быстро зайти, поправить код, погуглить, проверить API», хуже — для длительной dev-сессии с полным циклом правок, тестов, деплоя и ревью.
